Kronecker Embeddings V2 · Problem #5 · reverse the codec

The codec was invertible all along.

V1 made the input embedding a fixed, deterministic function of a token's bytes. That same function turns out to be exactly reversible — so the output side can predict a token's bytes instead of an id, and the d_model→|V| head disappears. No head means the vocabulary can be a million, or unbounded, at a constant cost.

forward "run" ──encode──▶ κ ∈ ℝ^{256×32} (column p = one-hot of the byte at position p) inverse κ ──argmax per column──▶ bytes ──utf8──▶ "run" ← exact output h ∈ ℝ^{d_model} ──▶ 32 × 257 byte-logits ──▶ next token ← no |V| anywhere

Proof 1 · a theorem you can touch

Encode a word, get it back exactly

Reshape the V1 codec κ(b) into a 256 × 32 matrix. Position p only ever writes to column p, and it writes a single scaled 1/√L in the row of its byte value. So columns never collide, and reading argmax down each occupied column returns the bytes. This is injectivity of the encoding — different from V1's cosine collisions (compute/commute), which are about two different tokens being close, not about κ losing information.

Proof 2 · why the head can vanish

Head size stops depending on the vocabulary

A softmax head is a d_model×|V| matrix — it grows forever with the vocabulary. The V2 head predicts 32×257 byte-logits regardless of |V|. Below ~8k tokens the softmax head is actually smaller (honest: V2 is a large-vocab technique). Past that, the lines diverge hard.

Proof 3a · it trains, and it keeps up

The invertible head matches softmax

Same GPT body, same Kronecker input, one corpus. The softmax arm predicts a token id; the V2 arm predicts the next token's byte-composition and is decoded with the paper's Hypothesis-A rule (score each vocab token by its summed byte log-probabilities). On next-token exact-match the two arms land together — both bounded by the grammar's irreducible entropy. The head is not the bottleneck.

Proof 3b · the payoff

It emits words it was never trained on

A delayed byte-copy task [w, SEP, w]: the model must re-emit w after a separator. Trained on 1,200 words, tested on 300 disjoint random words the weights never saw. The V2 head reconstructs 71% of them exactly — the misses are 1–2 bytes off, the cost of the lossy D→d_model projection. A softmax head reconstructs 0%: there is no output slot for a word outside its vocabulary. That is the whole point of "a vocab of 1M without any issues."

Proof 4 · the multimodal fix

When the next token is genuinely ambiguous

Proof 3a leaned on a vocabulary to decode. The invertible head's real weakness is codebook-free generation of an ambiguous next token: because it predicts byte positions independently, a point decode of “river or zebra or cloud” blends them into garbage. V1 §8.5's Hypothesis B is the fix — predict a distribution over codec space, not a point. We test three heads on a controlled task (12 contexts each followed by 3 fixed words; 6 deterministic), so the true distribution is known.

Proof 4b · on real text

The mixture head writes grammatical sentences

Folded back into the Proof-3a language model, the mixture head generates by sampling a component ∝ π and decoding it in codec space. Sampled continuations are grammatical — and its components line up with part of speech: after a determiner it proposes adjectives, after an adjective nouns, after a noun verbs.

The honest part

What it costs, and what's next

  • Per-position independence (categorical head). The kron_decode head treats byte positions as independent, so on ambiguous next-tokens a free byte-argmax blends modes (why free-byte accuracy is 0 on the LM task while the faithful vocab-restricted decode reaches parity). Proof 4 fixes this with the mixture-Gaussian head — coherent, calibrated, open-vocab multimodal sampling.
  • Mixture training is finicky at tiny scale. Recovering all K modes needs deterministic annealing + balanced (Sinkhorn) assignment + a mixing-weight entropy term; a plain mixture NLL mode-collapses, and the single diagonal Gaussian (paper-literal) cannot represent modes at all — kept as the instructive baseline.
  • Lossy projection. D = 8192 → d_model caps exact byte recall on long or rare tokens; the 71% unseen-word figure climbs with a wider d_model.
  • Break-even ~8k vocab. V2 only saves parameters above a few thousand tokens — a frontier-scale technique, exactly the regime V1 targets.

This is V1 §8.5 "Hypothesis A" — flagged there as untested. V2's contribution is turning it into a proven, trained result: exact invertibility, a head that is O(1) in |V|, parity with softmax, and genuine open-vocabulary output.
